# Distribution and operational readiness
1. Windows x64 spike: pin Python/node and package versions that actually install; build frontend (`npm ci`, `npm run typecheck`, `npm run test`, `npm run build`), backend (`python -m pytest`), PyInstaller on Windows from clean venv; spec adds `frontend/dist`, templates, licensed fonts and runtime binary hooks; smoke native bridge, OR-Tools, PDF/XLSX/DOCX generation. Do not claim Windows build from Linux.
2. Inno Setup: per-user install where feasible; detect WebView2 Runtime; bundle authorized Evergreen Standalone offline installer, check exit code/restart; do not silently fall back to obsolete browser engine. Test fresh offline VM, upgrade older DB, 125/150% DPI, no Python/Node/Office required for core export, non-admin permissions and paths with spaces/Unicode. Word viewing depends on user's reader, not generator.
3. Versioning SemVer and schema separate; pre-upgrade backup and verify before migration; transactional where possible, tested restore if migration fails; avoid downgrade on newer schema. Uninstall retains data by default; explicit removal separate confirmation.
4. Build artifacts: installer, SHA256, release notes, known limits, third-party notices/SBOM, user guide, offline activation/transfer instructions, restore instructions. Sign installer when feasible, communicate unsigned warning truthfully. Check license terms for redistributables and fonts; no paid templates/assets without permission.
5. Pricing Rp150.000 once per school for purchased major version; final support term and transfer policy before launch. Issue signed license file using separate offline signer not distributed in app. Test expiry/invalid signature/major-version mismatch; never lock export/backup. Beta uses explicit temporary entitlement; no surprise retroactive charging.
6. Pilot consent, collect metrics anonymously or manually with no student data shared; reproduce defects using synthetic records. Track bug severity: data loss/security P0, workflow blocker P1, minor P2. No automatic network telemetry. Create support checklist and log redaction export with user approval.
7. Release gate: test report and Windows native smoke evidence, migration and restore proof, solver validation, print preview inspected, no unlicensed dependencies, all P0/P1 accepted or explicitly descoped before advertising. Tag git, store immutable release and checksum; rollback installer does not downgrade DB automatically.
