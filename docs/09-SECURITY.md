# Security, privacy and data lifecycle
Threat model: stolen laptop, shared Windows account, unauthorized access to question files, malicious spreadsheet/template/backup, tampered licence, local filesystem abuse, crash/power loss, inadvertent disclosure in exports. Offline does not mean secure. Default OS account ACL; advise BitLocker/device encryption and dedicated OS user; SQLite plaintext unless explicitly encrypted, never claim otherwise. Optional local app PIN/role separation provides workflow protection only, not protection against an OS administrator. If password implemented, Argon2id/scrypt, no plaintext, recovery documented; show/hide UI. No hardcoded password, token or private signing key.

All bridge methods allowlisted, validate payload with Pydantic, scope by institution/event, optimistic revisions, sanitize errors, no exec/eval, arbitrary URL or file operations. File dialogs use approved extensions, byte/entry limits, magic/type checks, safe extraction no absolute paths/traversal/symlinks, atomic write, sandboxed template engine with allowlisted variables/filters and no arbitrary code. Disable macro-enabled files, external relationships, remote assets. Treat Excel formula cells as data issue; export text as literal not formula; protect identifiers. Images decode/re-encode, size limits, strip metadata as appropriate. Protect logs: no names/NISN/full paths to sensitive files, redact payloads; diagnostics user consent only.

Role model v1 operator local (single active writer); optional local app lock, explicit approval fields with actor label; no claim of strong nonrepudiation. P1 approval controls: supervisor/bendahara profiles if enabled, service checks on post/publish/archive; audit append-only within app, not tamper-proof against filesystem editing. No need to collect additional personal fields beyond requested documents. Export privacy mode omit NISN/photo/address unless required. Retention configurable; purge only with explicit confirmation and backup, preserve integrity. Follow applicable school policy and privacy law; do not present template as legal compliance certification.

Backup manifest: schema/app version, institution ID, timestamps, database and assets hashes. SQLite backup API consistent with asset snapshot under write lock; staged ZIP, checksum, atomically move. Restore validate manifest/paths/hash/schema, preview counts, backup current, stage isolated, swap only after integrity_check + FK check. Never overwrite current on failure. Keep optional encrypted external backup via OS/tool user controls; plain ZIP warning. Provide retention 7/30 copies configurable, avoid deleting last good backup. Test restore, not just creation.
